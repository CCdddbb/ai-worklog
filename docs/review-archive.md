# 审阅归档：结项、重新打开与批量操作

本轮把「人工审阅」从只改状态扩展为**可结项**：确认完成即归档，并同步结束该任务产生的自动记录。归档是本地状态整理，**不等于验收、不删除证据、不覆盖 AI 草稿**。

## 归档的含义

- 归档 = `tasks.status` 置为 `completed`，并把 `end_ts` 补到任务结束时刻（已有结束时间则保留；没有则取当天结束与当前时间的较早者）。
- 同一任务下的 `work_records` 写入 `archived_at`，报告里由「持续跟进」变为「已自动归档（非人工验收）」。
- 重新打开 = `tasks.status` 回到 `open`，并清空该任务自动记录的 `archived_at`；已存在的人工审阅文字、关联提交和证据快照都保留。
- 归档不修改 `summaries` 草稿、不改写历史进展、不删除会话材料。之后仍有新证据时，自动记录会重新出现为待核对。

## 单项操作

- 详情页底部按钮收敛为三种：**保存**（只存文字与状态）、**确认完成并归档**（主操作）、**重新打开**（仅已归档记录出现）。
- 「确认完成并归档」会先把状态设为已确认；**工作结果为空时拒绝归档**并给出内联提示，避免把空结论标成完成。
- 已归档记录顶部显示「已归档 · N 项自动记录已结束。可在下方重新打开继续跟进。」，不隐藏历史。
- 保存、归档、重新打开共用同一提交路径：请求期间按钮禁用并显示「保存中…／归档中…／打开中…」，成功后就地显示「已保存 ✓／已确认完成并归档 ✓／已重新打开 ✓」并附时间，失败显示可读错误并恢复按钮文字。

## 批量归档

- 列表每行新增复选框，勾选后出现批量条：显示已选数量、「归档所选」「重新打开」「清除选择」。
- 一次最多 50 项；确认框会说明后果（归档同时结束任务并移出待办；重新打开恢复为进行中）。
- 批量操作在一个事务内完成，任一项不存在则整体失败，不出现「一半已归档」。
- 状态筛选新增「已归档」；其他筛选（待核对、已确认、进行中、受阻）自动排除已归档记录，避免已完成项继续占用待办视图。
- 批量结果在批量条内就地反馈，并同步刷新列表与详情。

## 来源摘要与证据折叠

- 任务标题下改为一行来源摘要：`项目 · 会话数 · 起止时间 · 证据条数`，不再默认铺开每个会话。
- 会话明细放进可展开的「来源会话」，证据快照留在「证据快照技术详情」折叠区；预览入口仍在，但不再与审阅表单争夺注意力。
- 「本次审阅重点」默认只在存在待核对新草稿时展开；已记录的历史关注事项保持折叠，并显示关注项数量。

## 接口与校验

- `POST /api/task-review` 新增可选布尔字段 `archive`：`true` 归档、`false` 重新打开、缺省则只保存；非布尔值直接拒绝。
- 新增 `POST /api/task-archive`，请求体严格为 `{"task_ids": [...], "archived": bool}`；任务 ID 需为 32 位十六进制且不重复，数量 1–50。
- 两个接口都沿用既有的本地令牌认证、同源校验和写入白名单；未列出的路径返回 404。
- 归档后的状态以数据库为准返回 `archived`，前端不使用本地推测值。

## 已知边界

- 归档只结束本地任务与自动记录，不代表代码已合并、测试已通过或业务已验收；报告中仍标注为非人工验收。
- 批量操作按任务整体处理，不能只归档某个自动记录；单条记录的归档调整仍在任务归档视图中进行。
- 已归档记录不会自动清理；需要清理数据仍使用命令行 `purge`。
- 未实现撤销历史（只能重新打开）、跨任务合并归档和定时自动归档。

## 验证范围

- `python -m pytest`：**178 项通过**（含 11 个子测试），覆盖归档与台账联动、重新打开清空归档、无归档字段时保持原状态、批量校验与越权拒绝、API 认证与字段类型检查。
- 归档/重新打开的浏览器交互（复选框、批量条、内联反馈、按钮禁用态）本轮没有自动化用例；自动化覆盖停在 Python 接口与数据库层，前端行为只经过手动检查。

未验证：真实浏览器中的批量归档点击流程与键盘操作、真实模型草稿归档后的报告呈现、其他数据库规模下的批量性能、撤销与审计日志。
