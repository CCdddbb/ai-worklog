# 流程优化：首次使用引导与无模型手工记录

## 目标

延续「减少整理负担」主线（见 `docs/low-friction-review.md` 的后续优先项 1、2）。
上一轮补齐了链路末端的「复制今日日报」；本轮补链路前端：让用户不必猜当前处于什么状态，
并在没有模型授权时也能从单一会话一步进入人工记录。

## 本轮已实现

1. **首次使用引导**：新增只读端点 `/api/onboarding`（`worklog/onboarding.py`），状态判定放在 Python 侧，
   只依据已导入的本地元数据，不导入会话、不调用模型、不修改授权。首页 `#overview` 顶部渲染引导面板。
   - `empty`：整个数据库没有事件或导入记录 → 提示可能打开了另一个数据库，并给出 `--db` 启动命令入口。
   - `empty_day`：所选日期没有导入，但库里有其他日期记录 → 不误报为空库，提示先 import 或直接手工记录。
   - `unorganized`：当天已有会话但没有任何工作记录 → 提示可直接手工记录，无需启用模型或授权摘录。
   - `incomplete`：当天导入存在结构性读取缺口（`adapters.GAP_KEYS`，按日/时区隔离）→ 说明缺口不等于没有工作。
   - `demo`：虚构演示数据 → 明确不代表真实工作。
   - `ready`：已有记录，不显示引导。
   - 「已有数据库入口」以启动命令说明呈现：当前库由 `--db` 决定，浏览器不能切换或指定路径，
     不回传绝对路径，也不提供路径选择器。
2. **单会话快捷手工记录**：待整理会话新增「直接记录」按钮（`static/tasks.js`），复用原有的单会话建任务请求，
   但**不调用** `/api/summarize`、不检查模型/摘录授权、不产生费用确认框；创建后直接进入人工审阅表单，
   由用户填写结果，不自动保存、不自动确认为成果。原「生成总结」保持不变。
3. **自动记录模式下的同类入口**：自动整理开启时 `#legacy-workflow` 会隐藏，因此在会话树
   （`static/conversations.js`）为「所选日期有进展」的会话增加「直接手工记录」。
   限定当日有进展，是因为任务创建会拒绝不属于所选日期已导入事件的会话。
4. 把 `quickSummary` 中「查找或创建单会话任务」抽为 `singleSessionTask`，两条路径共用同一段逻辑。

## 验证

- Python **210 项测试通过**（原 200 项 + 新增 10 项）：`tests/test_onboarding.py` 覆盖六种状态、
  跨日缺口隔离、缺口字段白名单、演示数据、非法日期、手工/自动记录进入 ready；`tests/test_web_cli.py`
  覆盖端点鉴权/非法日期、首页引导容器与两处无模型入口的静态可用性。
- `node --check` 通过 `static/app.js`、`static/tasks.js`、`static/conversations.js`。
- 按项目约定未做额外真实浏览器视觉校验，也未自动化点选 macOS 原生交互；
  没有真实模型调用，不消耗模型额度。

## 明确边界

- 引导是只读提示，不自动跳转、不自动创建记录、不改变采集设置。
- 「直接记录」只创建任务并打开表单；人工审阅仍是唯一可信成果，AI 草稿不自动升级。
- 不增加默认模型调用、自动批量发送、后台常驻、摘录授权持久化，不扩大数据来源。
- 不迁移、切换或新建个人数据库；路径仍由启动命令决定。
- 引导面板只在首页展示；日期切换会重新请求，读取失败时隐藏面板，不掩盖主状态栏错误。

## 已知边界 / 后续优先项（本轮未做）

1. **记录编辑与删除的保留规则**：需先定义已生成草稿、人工结论及周/月报引用如何保留，
   避免无提示破坏历史；建议先定规则再实现。
2. 「复制今日日报」固定 `period=day`，后端 `detail=clipboard` 已支持任意周期；是否扩到周报/月报待定。
3. 粘贴到公司日报后是否在本地标记「已交付」，属于新增状态，未擅自引入。
4. 工作区仍只载入所选日期最近 100 条；超过上限的分页与按 ID 精确定位仍待做（见 `docs/task-workspace.md`）。
5. 会话树入口只覆盖当日有进展的对话；跨日历史对话仍需进入任务记录页手工新建。
