# 0.2.0 · 任务结束后的 LLM 总结

## 状态与边界

```text
用户关联1–12个同日会话 + 开始时间 → open任务
  ├─ 阶段总结 → queued → running → success / error → 任务仍open
  └─ 用户“结束并总结” → completed（仅用户结束记录）
                         → queued → running → success / error
```

任务的completed与模型成功/业务验收不是同一件事。模型不能改变任务状态。用户结束并成功排队后冻结结束时间；模型失败可显式重试，但不把后续新工作混入已结束记录。任务目前限定在所选日期，未实现多日自动归并。

自动模式每15秒检查条件，采集轮询默认30秒：只为本次服务启动后的新活动建立会话任务；相关活动停止默认10分钟且最后记录为自然结束、取消或错误边界时，生成阶段总结。未完成的用户输入、toolUse或deferred状态不直接当作结束。它不会自动完成任务，也不会把启动前的所有历史对话自动送往模型。

## 从原始记录到受限快照

1. 从已导入数据库中按会话与时间限定选择事件。
2. 用文件哈希定位显式配置目录下的对应JSONL，不接受浏览器传入文件路径。
3. 只提取所选用户/助手文本和工具状态。跳过思维链、图片、系统提示词、工具参数与输出；超过4000字符的整条消息省略，代码块省略。
4. 最多24条、每条最多500字符；为每个关联会话保留初始需求及近期结论，再补近期活动。披露采样范围和可用摘录数。
5. 对常见凭据、长编码串、邮箱、电话、网址、用户目录路径做尽力脱敏；不是通用DLP，不能保证去除一切商业秘密。
6. 冻结并持久化脱敏快照及指纹。查看“本次证据”返回实际模型输入快照，不用后来的日志冒充过去的材料。

重启后如果模型、摘录授权或来源目录范围改变，旧排队快照被阻止，不在新授权下继续发送旧材料。预览当前材料本身不调用模型；自动模式依据启动授权执行，不等待逐次确认。

## Pi CLI 隔离

在空临时目录中运行现有Pi，材料只经stdin输入；不放在命令行参数中。关闭tools、MCP、扩展、技能、上下文文件、项目批准、主题与会话持久化，禁止自动刷新模型目录。使用原生provider自行解析其既有凭据，本应用不复制密钥。

连续读取JSONL、以message_end为权威输出，并等待agent_settled；错误、截断、工具调用、未结束或JSON格式无效均不作为成功草稿。仅处理文本，不执行模型代码或命令。

输入限制50KB，快照限制48KB，输出限制1MB，诊断限制128KB，调用默认120秒。退出时仅终止本次新建的进程组，不杀用户的其他Pi或Chrome进程。

## 证据引用与费用保护

结果必须符合固定JSON结构：overview、work、results、blockers、next_steps。每一项都必须引用本快照的真实证据ID；未知引用会拒收。引用有效不代表语义一定正确，因此工作台和日报始终标为待审草稿，尤其results不是验收结论。

同一任务/阶段/模型/材料指纹去重；失败不无限自动重试。显式重试保留尝试记录，重复点击不会为同一重试并发创建多份。每个数据库只允许一个总结worker。

默认每日最多提交10个总结任务，执行阶段也检查按启动时间计算的当日上限，因此旧排队任务不能绕过今日执行额度。失败和被拦截的尝试也可能占名额。Pi本身的自动重试可能产生额外请求，任务数不是请求数或账单上限。

## 存储与清理

沿用原SQLite，新增tasks和summaries表；迁移保留已有事件及身份盐值。快照和草稿仍是潜在敏感信息，数据库未加密，不应提交到Git或发送给外部系统。

清理总结必须先停总结服务，避免清理后后台重新发送材料：

```bash
python3 app.py purge --db data/personal.sqlite3 --summaries-only
```

清理仅影响本应用的任务和快照，不删除源日志，不撤回云端供应商已处理的数据，也不删除已导出报告或备份。
