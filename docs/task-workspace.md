# 单项审阅工作区

## 本轮目标

不再把当天所有任务的草稿、证据和表单一起铺满页面。左侧选择工作，右侧一次处理一条，降低反复定位与重复审阅的成本。

## 已实现

- 单项详情编辑器；按全部、待核对、受阻、人工已确认、进行中筛选，搜索当前已载入的标题或人工结论。
- 右侧先展示本次重点；AI 原草稿/过程折叠，带入操作放到表单前部。结果输入全宽优先，验证和下一步分别填写，经验明确为可选。
- 保存与撤销放在表单顶部操作区；查看原草稿的证据与最新请求相同时，不重复展示两个证据按钮。
- 首页、报告和原草稿的入口会选中对应记录，而不是滚到另一条任务。
- 切换记录、筛选和日期时，未保存的审阅修订仍保留在本次 App/页面内存中；列表标识未保存状态。后台状态变化导致记录不再匹配筛选时，正在编辑的内容暂留并提示，不突然换走编辑器。
- 新建表单按需打开。新建草稿按日期隔离，切换日期后可返回继续；关闭新建表单不等于删除草稿。明确确认“放弃新建草稿”才清空这份未提交表单，不删除已有记录。
- 新建和保存期间阻止重复提交。即使保存中切换记录并重新打开编辑器，仍使用同一个在途保护；后续新文字保留为未保存修订，旧响应不能清掉它。
- 新建请求提交后切换日期，不把请求结果移到新日期，也不把已提交表单在返回时重新当作新草稿。
- 提交过程中不能用“撤销修订”假装撤回已经发出的请求；读取失败时先提示确认最新保存状态。未保存或在途工作会进入浏览器/原生退出检查。
- 日期切换期间清除旧日期的队列和编辑器；读取失败明确显示未加载成功，不显示假空记录。失败后的搜索不会把错误改成“没有匹配项”。
- 修复合法业务标题在 100 字时被静默截断的问题；本地存储保留经脱敏的最多 150 字标题，与表单/后端校验一致。模型证据的独立长度和授权边界不变。

- 修复四项合法中文长字段合计超过旧 16 KiB 请求限制而无法保存的问题：JSON 请求上限为有界 64 KiB，各字段仍最多 2000 字，超长字段和超大请求分别拒绝，不发生半份保存。

## 验证

- Python **148 项测试通过**，包括任务总数/载入上限、日期隔离、合法长标题、SQLite 只读连接与并发读写回归。
- 真实 Chrome 任务工作区验收：单编辑器、状态/搜索、焦点及选区、跨记录/日期草稿保留、后台筛选变化、重复提交、保存中跨记录编辑、创建中继续输入、跨日期返回、校验失败保留、读取失败恢复。
- 浏览器还回归了原有总结/带入/人工保存、报告与 PDF、周卡片和折线。没有真实模型调用或外部页面请求。
- 320 / 390 / 768 / 1440px 无页面横向溢出；新建和单项审阅分别只显示一个蓝色主操作。手机选择记录后直接定位详情，可用“选择其他记录”返回列表。
- macOS App 已从当前源码重建；本地 ad-hoc 签名严格校验、实际 WKWebView smoke、退出后无后台残留通过。核对了关键打包资源与源码哈希一致，包内不含数据库、身份密钥、日志或 SQLite 附属文件。
- 未自动化点选 macOS 原生未保存提示；原生 smoke 仍用于实际 WKWebView、服务连接、周页、报告及返回导航，不把它当作所有原生交互已验证。

## 已知边界

- 当前每次只载入所选日期最近 100 条。接口和页面披露总数以及载入范围，搜索/状态计数不冒充全天全量。完整报告仍可汇集全部记录；超过 100 条时的分页与按 ID 精确定位留待后续。
- 草稿只保存在本次进程/页面内存，不是崩溃恢复或自动保存。正常关闭前需要明确保存；强制结束进程仍可能丢失未保存文字。
- 不自动把 AI 结论确认为成果，不增加模型调用或扩大数据源授权，不进行个人数据迁移。

主要实现位于 `static/tasks.js`、`static/workbench.css`；验收脚本是 `tests/task-workspace-browser.cjs`。
