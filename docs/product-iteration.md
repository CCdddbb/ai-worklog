# 产品迭代：任务、人工审阅与周期报告

## 用户流程

1. 运行 `python3 app.py start --db data/personal.sqlite3`。程序发现本机存在的 Pi/Codex 会话目录，读取日志并启动本地页面。默认不调用模型、不发送摘录。
2. 首页显示已记录任务，以及尚未归入任务的会话。进入“任务记录”，选择同一工作任务的一个或多个会话；匿名项目相同只是辅助选择，不能证明它们属于同一任务。没有 AI 会话也可创建手动任务。
3. 可选择预览证据并生成 AI 草稿。草稿需要人工审阅；保存人工审阅时，填写“进行中/已确认/受阻”、工作结果、经验、验证方式和下一步。再次保存会更新记录。
4. 显式传 `--git-repo` 时，程序只读取这个仓库的提交哈希、时间、标题、文件数和增删行数。任务卡片允许人工关联当日提交。不会读取或保存 diff、文件内容和仓库绝对路径；提交不自动证明需求完成或测试通过。
5. 日报、周报和月报按所选日期生成。周期报告只把人工审阅记录写入任务结果；模型草稿不会自动升级为确认成果。使用统计仍单列参考。

## 仍需人工判断的边界

- 任务当前按单日创建；跨日任务需要分别记录，周期报告按日期列出，不会自动归并成唯一任务。
- Git 提交是代码活动线索，不能代替测试报告、部署记录或业务验收。验证方式目前由用户填写。
- 每次 Git 导入最多查看指定日期的前 100 个提交；如果超过上限，导入结果的 `more_commits` 会提示覆盖缺口。
- 自动发现只覆盖默认 Pi/Codex 日志目录；需要限制来源时用 `serve --watch` 显式配置。Git 仓库始终显式指定。
- `--allow-excerpts` 仅用于可选模型总结，仍是尽力脱敏。人工审阅文本保存在本地 SQLite 中，不会自动发给模型。
- 周报、月报的 Token 数来自已导入日期，不代表完整工时或账单。

## 数据清理

- `purge --summaries-only` 删除任务、人工审阅、关联关系、AI 草稿及回顾状态；保留已导入的 Git 提交元数据。
- `purge --before YYYY-MM-DD` 删除指定日期之前的会话事件、Git 提交以及过期任务的审阅和关联记录。
- 清理不会删除源日志、Git 仓库、已经导出的报告或外部备份。
