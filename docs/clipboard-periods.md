# 迭代：复制报告支持日报 / 周报 / 月报

## 目标

`docs/flow-optimization.md` 的后续优先项 2 指出：「复制今日日报」固定 `period=day`，而后端
`/api/report?detail=clipboard` 早已支持任意周期。本轮把这条已具备的能力接到界面上，并处理
长周期带来的新问题：周报、月报条目更多，原先的条数上限会静默丢内容。

## 本轮已实现

1. **周期可选**：首页顶部原「复制今日日报」改为「复制报告」，旁边新增「复制周期」选择器
   （日报 / 周报 / 月报，默认日报）。复制时按选择器当前值请求 `period`，所选日期决定周/月的归属；
   状态栏说明实际复制的周期与范围，例如「本周周报已复制（所选日期所在周）」。
2. **单一数据源**：剪贴板文字仍来自同一份报告文档的 `clipboard_digest`，与页面报告、Markdown
   导出共用数据；没有新增端点、没有第二套汇总逻辑，也没有调用模型或修改任何记录。
3. **不再静默截断**：`clipboard_digest` 按周期调整上限——日报每节 30 条、下一步 12 条，
   周报/月报每节 60 条、下一步 24 条。超出上限时明确写出「另有 N 条未列出，详见工作报告」；
   「需关注 / 待核对」的汇总提示始终保留，不会被截断挤掉。周/月报标题与日期区间来自
   `period_days`，「今日完成」相应改为「本期完成」。
4. **返回位置保持一致**：切换视图后按「返回」会恢复本次选择的复制周期，和报告周期、审阅版
   等位置信息一同保存。非法选择器值回退为日报，不会把非法 `period` 发往后端。

## 验证

- `tests/test_web_cli.py`：三个周期都返回 `text/plain` 纯文本、各自标题与区间、无 Markdown
  章节；非法周期与非法 `detail` 均返回 400；首页静态控件与前端脚本不再硬编码 `period=day`。
- `tests/test_documents.py`：周报 / 月报标题与区间、本期完成，以及日报 31 条、周报 70 条、
  月报 61 条、下一步 30 条时的显式省略提示。
- 全量 `unittest discover -s tests` 220 项通过；`node --check static/app.js` 通过；`ruff check .` 干净。
- 按项目约定未做额外真实浏览器视觉校验；剪贴板写入依赖浏览器 `navigator.clipboard`，
  此处只验证请求参数、返回内容与静态控件可用性，未自动化点选真实剪贴板。

## 明确边界

- 只在首页展示复制控件；周报/月报的正式排版与 Markdown 导出走原有「工作报告」页面，未改动。
- 不新增「已交付」状态、不记录复制历史、不写入浏览器存储，也不改变自动整理设置与用量授权。
- 剪贴板文字依然是精简版：不含用量统计、采集覆盖说明和证据附录；长周期仍可能省略条目，
  但省略数量可见，完整内容请看工作报告。
- 工作区最近 100 条上限、跨日历史会话的手工记录入口、记录编辑与删除的保留规则仍未处理，
  见 `docs/flow-optimization.md` 的后续优先项。
