# 报告质量与重点审阅迭代

## 目标

不以自动确认代替质量。把“重读整篇草稿”变成“核对具体缺口”，把工作报告从使用统计改为成果、风险和行动。

## 已实现

- 日报、周报、月报统一为结构化报告：人工成果优先，其后是重点关注、推进、阻塞、未审阅工作、下一步和每日图表；Markdown 与页面使用同一份报告文档。
- 默认「精简交付版」保留结果、状态、验证与下一步；「完整审阅版」展开问题、措施与证据索引。任何版本都保留失败、阻塞、未验证和仅讨论边界，不用省略风险换取简短。
- 已有人工结论的工作不再重复输出同一 AI 草稿；人工审阅后产生新草稿时，保留旧结论并标注“新增内容待核对”，不继承旧确认状态。
- 重点提示包括：报告解决但缺少验证、人工确认未填验证、明确阻塞、仅讨论未实施、抽样材料、旧版不合格草稿、审阅后的新草稿。它们是规则提示，不是语义验收或可信度评分。
- 报告可筛选「只看需关注项」，并直达对应日期的审阅表单。筛选不影响完整导出；打印前恢复全报告，避免意外漏报。
- 原文依据来自该草稿的冻结快照，可按具体工作展开，不拿后来的日志冒充过去证据。任务卡另提供「核对草稿原文」，与最新失败请求的证据区分。
- 不同日期的人工记录只有在标题、状态、结论、验证、经验、下一步、关联提交和原草稿内容都相同时才合并展示，并保留全部日期和数量。相同日期的不同任务、新草稿待核对的记录不合并。原记录和每日统计均不改变，不声称它们是同一个业务任务。
- 下一步的完全相同文字可汇集展示并保留来源、日期和记录数量；不重新引入人工已删除的旧 AI 建议。
- 报告页是真实标题、卡片和图表，不执行 Markdown/HTML。源文可折叠查看。支持浏览器打印保存 PDF；macOS App 提供原生打印入口，Markdown 下载保留。
- 修正按日覆盖披露：使用日期/时区对应的采集记录，不能拿其他日期的最新扫描证明本期覆盖。未记录仍明确标注。

## 验证

- Python **141 项测试通过**。新增人工优先、旧草稿去重、新草稿待核对、验证缺口、阻塞/讨论/抽样提示、同文展示边界、精简/完整版内容保真、日期覆盖、鉴权与预览/导出一致性测试。
- 真实 Chrome 使用虚构业务证据：登录修复且生产回归未做、筛选仍有两个失败用例、桌面仅讨论。核对界面及导出不把三者混成全部完成。
- 验收样本有 10 条原记录；精确同文合并后展示 5 组，统计仍为 10 条。需要重新核对的记录为 2 条，其他关注项明确是已记录的阻塞，不要求重复确认旧草稿。
- 已验证简版/完整版切换、关注筛选不改变导出、原文展开、直接进入审阅、HTML 注入不执行、日/周/月在 320/390/768/1440px 下无页面横向溢出。
- 已生成实际 A4 PDF 并用 PDFKit 检查页面和文字，无空白页，无侧栏、跳转链接或技术源文混入。验收样本的精简 PDF 为 4 页，不声称任意报告都是一页。
- 测试不调用真实模型，不消耗模型额度。原生打印对话框的点选、不同系统版本的分页不在自动化验证范围内。

## 使用

网页或 App 打开「工作报告」，选择周期与报告版本。需要核对时选择「只看需关注项」，展开对应依据或点击「前往核对」。正式交付用右上角 Markdown 导出，或报告页的「打印 / 保存 PDF」。

```bash
python3 app.py report --db data/personal.sqlite3 --period week --detail brief
python3 app.py report --db data/personal.sqlite3 --period week --detail full
```

主要实现：`worklog/documents.py`、`worklog/review_focus.py`、`static/reports.js`。
