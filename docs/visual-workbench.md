# 工作台体验重构：工作优先、语义操作与周趋势

## 本轮范围

按已确认方案先完成首页、统一视觉语义、七日记录卡片与使用折线。保留既有任务页和报告流程，不在本轮扩展新数据源、增加模型调用或重做任务数据模型。

## 首页

- 首屏顺序改为：待核对 / 人工受阻 / 待整理会话 / 人工确认成果 → 需要处理的工作 → 今日成果 → 按需展开的 AI 草稿与设置。
- 「开始整理」会优先进入待核对工作，其次进入受阻记录，否则打开手动记录；不会自动调用模型。
- 人工已确认成果不再混在待处理队列。仅显示少量成果摘要；已审阅 AI 草稿折叠归档，首页不展开完整问题/措施/证据。
- 小时柱形与模型条形对比移至「使用分析」，保留它们适合的数量比较用途。
- 改名、暂存和主题提取移入「更多」，避免每行三四个同权重按钮。

## 今日时长分布

- 首页「今日成果」之后新增环形图，按任务标题汇总所选日期的已归因活跃估计，最多显示 6 个扇区，其余合并为「其他」；图例同时给出时长与占比。
- 总时长取各记录活跃估计之和，并行区间已在后端去重后分摊；存在未归因观察区间时在脚注披露，不按比例补造。
- 没有任何活跃估计时整块隐藏，不显示空图或零值占位；读取失败同样隐藏，避免留下上一日期的旧图。
- 扇区可用键盘聚焦，SVG 提供文字摘要；颜色沿用现有橙、蓝、绿、紫、琥珀与中性色，不引入新色板。

## 视觉密度收敛

- 项目与对话树：项目、会话标题统一为 14px，会话列表改左侧竖线缩进，替代逐级放大的字号；标题间距同步收紧。
- 首页「今日时长分布」改为细环：环宽降为 12，扇区间留 2 单位缺口，总时长移到环心文字层；图例压缩到 12px 并单行省略长标题。
- AI 使用趋势图：坐标与日期文字全部移出 SVG，改为图上方的「峰值 / 有记录天数」说明和图下方的七日数值按钮（统一 12px / 16px 行高）；网格与折线用 `non-scaling-stroke`，手机端抬高绘图区。

## 视觉语义

- 蓝色实心：当前区域的主操作，例如首页核对与保存审阅。
- 浅紫色：AI 生成、重试、带入草稿，与人工确认区分。
- 中性描边：预览、导出等次操作；文字样式：返回、改名等辅助操作。
- 绿色状态：人工确认；蓝色：人工进行中；橙色：阻塞或缺口；紫色：AI 草稿/待核对；灰色：未记录/结束记录等中性状态。
- 所有状态同时带文字，不仅依靠颜色。审阅后出现新草稿时，队列标为紫色待核对，旧人工结论仍保留在成果区，不把新 AI 内容涂成已确认。
- 新增独立的 `static/workbench.css` 作为工作台视觉层，不引入字体、图表 CDN 或外部前端依赖。

## 周记录

- 七日卡片展示每一天的实际工作摘要和状态，选中后在下方查看该日记录；手机用可横向滚动的七日卡片栏。
- 使用 SVG 折线显示 Token / AI 回复 / 会话变化，不做平滑或外推。
- 已扫描/有记录且观察值为零：真实零点。没有记录：断开折线并显示破折号。采集存在缺口：提示不完整，不伪装为全量。
- 图表旁提供七天的实际数值按钮，支持触摸与键盘，不依赖悬停。点折线数据点或数值可打开当天；卡片选择保持在周页查看进展。
- 空周仍显示七天，但无伪造数据点。请求失败显示错误并清空旧图表，不显示一张假零值图。
- 周页面隐藏重复的单日选择和报告周期控件，导出固定为当前周。报告页仍可独立切换日/周/月。

## 审阅保存稳定性收尾

- 修复普通「保存」审阅必定被拒收的问题：前端把 `archive: null` 一起提交，后端要求该字段为布尔或缺省；现在仅在布尔时携带。
- 修复保存成功后保存按钮可能永久禁用：先退出保存态再刷新；焦点保护延迟重渲染时，同步恢复当前卡片上的保存按钮。
- 浏览器测试更新主按钮选择器（`button.primary, button.button-primary`）并复验以上两条路径。

## 验证

- Python 184 项测试通过，包括新视觉样式的本地静态资源路由、读取不产生多余数据库写入以及并发保存/读取回归。
- 浏览器测试覆盖首页可见主按钮数量、AI/人工状态区分、首屏工作入口、今日时长分布（有记录显示环形图与图例、无记录隐藏）、七日选择、数据点/空白/零值、缺口断线、空周、请求失败恢复、周报导出周期和原有审阅/报告流程。
- 对蓝色主操作、紫色 AI 操作、紫/橙/绿状态文本的实际计算颜色检查达到 4.5:1 对比度；不声称已完成整个应用的无障碍审计。
- 在 390×844 的手机视口中，首个待处理工作按钮无需滚动即可看到；320 / 390 / 768 / 1440px 布局检查无页面横向溢出，卡片栏的横向滚动仅限其容器。
- 全部视觉测试使用合成记录，不读取个人会话、不产生模型费用。截图在 `/tmp/worklog-report-redesign/` 和 `/tmp/worklog-week-redesign/`。

## 稳定性收尾

- 曾观察到一次快速总结后切换周页的测试超时，连续 5 次复跑未再复现。已为失败测试增加不含令牌的 HTTP 状态与 UI 状态诊断，不能据此宣称已证明该单次超时的唯一根因。
- 另以 SQLite `data_version` 证实：原连接函数在读取已拥有且结构不变的数据库时仍重复写入 application_id。现在只在需要设置所有权标记时写入，避免不必要的读请求写锁。新增回归验证重复读取不改变数据版本，以及并发保存 20 次审阅、读取 24 次日/周/报告 API 全部成功。
- 原生 WKWebView smoke 已验证新版周页、从周页进入周报、返回导航及后端退出清理；本地 App 已包含新视觉样式。测试对“周页进入报告”的预期已从日报更新为正确的周报。
- 本轮未推送 GitHub，未修改任何个人数据库或模型授权。
