# 迭代：减少个人整理负担

## 已确认目标

用户选择优先「减少整理负担」，而非先做对外报告或项目管理。当前优化主线：会话待整理 → 生成草稿（另需授权）→ 带入表单 → 人工核对 → 保存 → 周记录汇集。

## 本轮已实现

1. **从 AI 草稿带入**：仅对具备有效正文证据的新版草稿开放。可选择全部工作项或单个工作项，把结果、验证、下一步带入表单，不再次调用模型。经验与提交关联保留，状态回到进行中；不自动保存或确认为成果。替换已有文字前确认。内容超长会阻止带入并提示分项选择，不静默截断。
2. **不中断编辑**：任务卡按 ID 和实际变化更新，正在编辑的输入区保留节点、焦点与选区。切换日期后返回仍有本次内存草稿；可撤销未保存修订。保存期间继续输入时，新内容仍标记未保存，不被旧响应删除。
3. **会话暂不整理**：只暂存当天尚未关联任务的会话，不删除日志或统计、不自动归为成果；可恢复。以事件 ID/时间/状态的摘要判断新活动，新增工作消息会重新提醒，同时间戳的新消息也不会遗漏。纯用量更新或重复导入不重复提醒。自动模式尊重同一暂存状态。
4. 首页任务提供直达审阅入口；暂存会话集中在可展开区域，待整理超过五条时提供完整整理入口。
5. 浏览器离开页时提示未保存修订；桌面 App 退出、重新连接、切换数据库前检查未保存文字。内存草稿不额外持久化到浏览器存储或发送模型，崩溃仍可能丢失，需明确保存。

## 验证

- Python 128 项单元/集成测试通过；新增暂存持久化、恢复、同时间戳新活动、纯用量更新、跨日/时区隔离、非法范围、自动模式、令牌和 Origin 校验。
- 真实 Chrome 假模型流程通过：暂存/恢复计数、带入不调用模型/不自动保存、不自动确认、撤销、编辑焦点/选区、跨日期保留、保存中继续输入的竞态，以及后续日报/周报与下载回归。
- macOS 原生提示的交互点选尚未自动化，不将编译和页面 smoke 当作所有原生交互已验证。

## 后续优先项（不是本轮已完成）

1. 首次使用引导：在 App 内明确区分空库、已导入但未整理、采集失败；给出已有数据库入口，而不是让用户猜。
2. 为单一会话添加不调用模型的快捷手工记录，减少模型授权不足时的绕路。
3. 工作记录编辑与删除：需要明确已生成草稿、人工结论及周报引用如何保留，避免无提示破坏历史。
4. 正式报告排版与图表导出，排在日常整理闭环之后。

本轮不增加默认模型调用、自动批量发送、费用授权、隐私授权持久化或后台常驻；没有自动迁移个人数据库，也未推送 GitHub。
