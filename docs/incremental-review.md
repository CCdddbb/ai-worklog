# 0.3.0 · 命令行增量回顾

## 使用约定

本地命令主动回顾日志，而非监控整机，也不会检测用户是否真的关闭了会话。
首次 `--start-now` 是起点，以后每次成功回顾消费明确的一组事件；无需网页或常驻进程。
默认入口 `bin/worklog-review` 使用仓库 `data/review.sqlite3`，只选择用户的 Pi 会话目录。
Codex 可显式加入，来源目录组合各有独立状态，不能默默扩大旧授权。

```bash
./bin/worklog-review --start-now --allow-excerpts
# 工作、结束一个或多个 AI 会话，然后：
./bin/worklog-review
# 每次最多一批，控制单次模型调用规模：
./bin/worklog-review --batch-limit 1
# 先看选中的脱敏材料；不调用模型、不消费事件：
./bin/worklog-review --preview
# 只显示已保存结果：
./bin/worklog-review --last
# 当前来源以后不再发送对话摘录（本次仍可能发匿名元数据）：
./bin/worklog-review --metadata-only
```

首次若要回顾历史，使用带时区的 `--since` 替代 `--start-now`。
已有起点不能重新设置以跳过积压；确需另一套时间边界请使用独立 `--db`。

完整入口示例：

```bash
python3 app.py review --db data/review-both.sqlite3 \
  --pi-dir "$HOME/.pi/agent/sessions" --codex-dir "$HOME/.codex/sessions" \
  --start-now --allow-excerpts
python3 app.py review --db data/review-both.sqlite3 \
  --pi-dir "$HOME/.pi/agent/sessions" --codex-dir "$HOME/.codex/sessions"
```

## 输出与“流式”的含义

命令先输出日期范围、覆盖缺口和模型，再逐批输出**已通过结构及引用验证**的工作条目，例如：

```text
## 批次 01 · 调整开发环境并核查接口
活动：… → …
* 01 工作条目：调整 IDE 终端显示，仍需实际界面核验。（证据：e_…）
* 02 工作条目：核查接口参数和错误线索。（证据：e_…）
- 阻塞：尚无环境验证结果。（证据：e_…）
本次回顾 20 条活动；还有 0 条留待下次。
```

这是按已验证条目/批次即时 flush，不是逐 token 展示原始模型回答。
同一批中的重复尝试应合并，不把“retry”认定为新成果。
批间/跨工具同一业务任务仍可能重复出现，并不声称已经实现全局业务语义去重。
助手声称完成、用户结束会话、模型正常返回均不代表业务验收。

## 去重、重试与范围

- 开始导入前冻结读取截止时间。此次导入之后新出现的事件留给下次，哪怕其时间戳较早。
- 只处理当前来源本次实际导入的事件，不把同数据库其他目录的事件混进来。
- `review_seen` 按来源范围、匿名事件ID及状态摘要记账。每次从初始起点重扫，迟到事件不会因时间水位线而消失；已有事件的状态发生变化也会再次报告。
- 选择用户消息、非 toolUse 的助手消息、错误/结束边界及失败工具状态。普通工具输出、参数、思维链不进入材料；纯用量更新不产生工作条目。
- 时间排序后拆成最多24事件、12会话的批次，批内不丢弃中间事件。每次默认最多4批，剩余明确提示并留待下一次；最大12批，不是每日额度或费用封顶。
- 各批的脱敏输入只在内存中存在。本地缓存只保存输入指纹、已验证输出和用量；新源文本、模型或摘录授权变化会改变指纹，不复用不匹配的结果。
- 所有选中批次都输出成功、可选 `--out` 写入成功后，在单个SQLite事务中写报告并消费事件。失败、取消、断管不消费；已经打印的批次可能在重试时再次显示，但可以复用模型结果，避免相同调用。
- 每个库有非阻塞独占回顾锁；两个回顾进程或总结清理操作不能并行改写回顾状态。
- 源文件读取仍然有500文件上限（可调小）、64MiB文件上限、2MiB行上限。过长行若能从截断前的顶层JSON头部解析到窗口外时间，会单独披露而不阻断；不会匹配消息正文中的嵌套时间戳。窗口内或时间未知的过长行，以及其他读取缺口，默认仍拒绝总结。`--allow-partial` 是明确接受不完整结果，永远披露覆盖。缺口只统计与时间窗相关的文件：最后写入时间早于窗口起点的文件不读取、也不计入缺口；窗口内超过64MiB的文件改为读取到上限并披露截断，不再整文件丢弃。

## 隐私与清理

摘录默认关闭，`--allow-excerpts` 会把此来源范围的授权保存在本地，后续同命令可继续调用所选模型。
每批最多24条、每条500字符，只使用受限脱敏文本。长消息和压缩历史摘要会省略，因此不能还原全部上下文。
关键词脱敏无法识别所有业务秘密；调用前可 `--preview` 检查，遵守公司政策。
模型通过既有隔离 PiRunner 运行，禁工具/MCP/扩展/技能/上下文文件/会话持久化；不会执行日志中的指令。
不把真实对话拿来做开发过程的云端测试。

报告/缓存/身份盐值位于本地私有数据库目录，不进入 Git。SQLite权限0600但未加密。
标准输出中显示过、人工导出或备份过的报告不会随数据库清理消失。

```bash
# 停止回顾和总结服务后执行；清除生成结果、缓存、已消费事件及摘录授权/起点。
python3 app.py purge --db data/review.sqlite3 --summaries-only
```

该操作保留匿名导入事件，后续回顾需要重新显式初始化起点；不会清理原始 Pi/Codex 日志。
`purge --before` 也会删除该日期以前生成的回顾及全部回顾结果缓存；保留去重台账避免把旧事件再次当新工作。

## 验证

新增21项自动化测试覆盖初始化、去重、迟到/同时间戳/跨日事件、模型失败后的缓存恢复、批数预算、
预览与脱敏、撤销摘录授权、覆盖缺口、输出失败/禁止覆盖、引用校验、模型运行中新增活动、状态变化、
回看导出/清理、Codex来源隔离、进程锁及身份盐值保护。与原有55项测试一起共76项通过；也验证了历史超长行与窗口内缺口的区分、顶层时间戳解析不会匹配嵌套消息文本。
模型结果使用确定性假模型验证命令闭环，并用合成 Pi 子进程验证 stdin、禁工具参数、JSON流解析和持久化；真实模型的安全调用层沿用0.2.0既有验证。
没有宣称真实个人多日回顾已验收，也没有自动提交、发布、开机启动或定时外部推送。
